# happ2mihomo

[English](README.md) | Русский

`happ2mihomo` — это локальный адаптер в Docker, который загружает JSON-подписку Happ и предоставляет для Clash Verge Rev строго сформированную YAML-подписку Mihomo.

Сервис поддерживает VLESS TCP+Reality, VLESS TCP+TLS, VLESS WS+TLS и профили Happ Hysteria версии 2. Проверенный агрегат Happ с несколькими исходящими подключениями распознаётся и не включается в сформированный список прокси. Compose публикует сервис только на loopback-интерфейсе хоста.

## Выберите один способ запуска

Требования: Docker Engine с Compose v2 в Linux или Docker Desktop в macOS.

Оба варианта выполняются из каталога репозитория. Создайте приватный файл окружения:

```sh
(umask 077; cp .env.example .env)
```

Отредактируйте `.env` и замените заполнитель `REPLACE_ME` в `SUBSCRIPTION_URL` на HTTPS-адрес подписки Happ. Конфигурация с заполнителем не работает. По умолчанию используется User-Agent `Happ/4.3.0/Android`. `HOST_PORT` — локальный порт macOS или Linux; это должно быть свободное целое число от `1` до `65535`. Не используйте `0`, иначе Compose выберет непредсказуемый порт хоста. Если файл `.env` уже существует, перед его редактированием выполните `chmod 600 .env`.

### Вариант A: Compose CLI

Соберите и запустите сервис из командной строки. Если вы хотите запускать его кнопкой Play в Docker Desktop, пропустите эти команды и используйте вариант B.

```sh
docker compose up -d --build
docker compose ps
```

При стандартном значении `HOST_PORT=17890` локальные адреса выглядят так:

```text
http://127.0.0.1:17890/sub
http://127.0.0.1:17890/healthz
```

Например, при `HOST_PORT=18080` адреса изменятся на `http://127.0.0.1:18080/sub` и `http://127.0.0.1:18080/healthz`. Порт контейнера останется равен `17890`.

### Вариант B: регистрация в Docker Desktop и кнопка Play

Этот вариант регистрирует Compose-приложение без предварительного запуска `docker compose up`, чтобы впоследствии его можно было запускать кнопкой Play в Docker Desktop. Названия элементов интерфейса macOS могут отличаться в разных версиях Docker Desktop; проект не проверял этот сценарий через графический интерфейс macOS.

1. Запустите Docker Desktop, клонируйте или откройте этот репозиторий и откройте терминал в его корневом каталоге.
2. Создайте и отредактируйте `.env`, как описано выше. До регистрации выберите порт хоста, например:

   ```dotenv
   HOST_PORT=17890
   ```

3. Соберите и создайте приложение, не запуская его:

   ```sh
   docker compose create --build
   docker compose ps --all
   ```

   Сервис должен отображаться в состоянии `created`. На этом этапе Compose сохраняет сопоставление портов `127.0.0.1:${HOST_PORT}:17890`.

4. В Docker Desktop откройте раздел **Containers**, разверните приложение `happ2mihomo` и нажмите Play. Дождитесь, пока контейнер перейдёт в состояние healthy, затем выполните описанные ниже быстрые проверки.

После изменения `.env`, обновления исходного кода или загрузки новой версии пересоздайте остановленный контейнер, прежде чем снова использовать Play:

```sh
docker compose create --build --force-recreate
```

Чтобы пересобрать, пересоздать и сразу запустить контейнер, выполните:

```sh
docker compose up -d --build --force-recreate
```

## Быстрые проверки и управление жизненным циклом

Эндпоинт состояния проверяет работоспособность локального HTTP-процесса. Он не загружает и не проверяет подписку из внешнего источника.

```sh
curl --fail --silent --show-error http://127.0.0.1:17890/healthz
```

Точное содержимое ответа:

```json
{"status":"ok"}
```

Убедитесь, что подписку можно загрузить и преобразовать, не выводя сформированную конфигурацию прокси:

```sh
curl --fail --silent --show-error --output /dev/null http://127.0.0.1:17890/sub
```

Если `HOST_PORT` отличается, замените `17890` в обеих командах. Проверить состояние и журналы можно командами:

```sh
docker compose ps --all
docker compose logs --tail=100 happ2mihomo
```

Команды управления жизненным циклом действуют по-разному:

```sh
docker compose stop     # остановить, сохранив регистрацию в Docker Desktop
docker compose start    # запустить сохранённые контейнеры
docker compose down     # остановить и удалить контейнеры и регистрацию
```

Устранение неполадок:

- Если при запуске сообщается, что порт уже занят, выберите другой свободный `HOST_PORT` в `.env` и пересоздайте контейнер.
- Ошибки стартовой конфигурации намеренно содержат только имя параметра. При использовании Compose сообщения `Invalid configuration: SUBSCRIPTION_URL` или `Invalid configuration: HAPP_USER_AGENT` могут многократно появляться в журналах, потому что политика перезапуска повторно запускает аварийно завершившийся контейнер; убедитесь, что `SUBSCRIPTION_URL` больше не содержит `REPLACE_ME`. Ошибка `Invalid configuration: PORT` возможна только при непосредственном запуске Node.js или переопределении окружения контейнера, поскольку Compose всегда фиксирует `PORT=17890`.
- После изменения `.env` или образа пересоздайте контейнер: обычный перезапуск сохраняет его прежнюю конфигурацию. Если сервис остаётся в состоянии `unhealthy`, обратитесь к `/healthz`, проверьте вывод `docker compose logs`, затем пересоберите и пересоздайте контейнер.
- `502 Bad Gateway` означает, что ответ поставщика, перенаправление или полное содержимое Happ были отклонены, в том числе из-за ошибки проверки преобразования.
- `503 Service Unavailable` означает, что достигнут предел в четыре одновременных запроса или процесс завершает работу.
- `504 Gateway Timeout` означает, что запрос к внешнему источнику не завершился за 20 секунд.
- `404 Not Found` указывает на неизвестный маршрут; `405 Method Not Allowed` — на использование метода, отличного от `GET`.
- `500 Internal Server Error` означает непредвиденную локальную ошибку; проверьте журналы контейнера.

## Добавление профиля в Clash Verge Rev

1. Откройте в Clash Verge Rev страницу профилей или подписок.
2. Добавьте или импортируйте удалённую подписку с адресом `http://127.0.0.1:17890/sub`, заменив порт в соответствии со своим значением `HOST_PORT`.
3. Сохраните или обновите подписку, выберите импортированный профиль и убедитесь, что в нём появились прокси, прежде чем включать системный прокси или режим туннеля.

Точные названия элементов управления зависят от версии. Актуальное описание интерфейса и поддерживаемых способов импорта по URL приведено в официальной [документации профилей Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md).

## Строгое преобразование

Подписка обрабатывается атомарно и по принципу fail-closed. Каждый элемент должен быть либо отдельным поддерживаемым профилем, либо структурно распознанным агрегатом. Неподдерживаемый отдельный профиль, некорректный прокси или агрегат, отсутствующий селектор, ссылка на балансировщик или резервную цель агрегата, а также неизвестный вариант агрегата приводят к отклонению всего ответа `/sub` с кодом `502 Bad Gateway`; некорректные элементы никогда не отбрасываются молча. Подписка, содержащая только агрегаты, также отклоняется, поскольку в результате получилась бы пустая конфигурация Mihomo.

Распознанный агрегат имеет непустое корректное поле `remarks` и обладает всеми следующими свойствами:

- не менее двух строго корректных исходящих прокси VLESS или Hysteria 2 с уникальными непустыми тегами;
- один или несколько балансировщиков маршрутизации с уникальными тегами; каждый префикс селектора соответствует хотя бы одному прокси, список селекторов каждого балансировщика выбирает не менее двух прокси, а все балансировщики вместе охватывают каждый прокси;
- действующие правила маршрутизации ссылаются на каждый объявленный балансировщик и не ссылаются на неизвестные балансировщики; поле `outboundTag` обычного правила должно быть непустой строкой-идентификатором, но не обязано называть исходящее подключение агрегата, а если указаны обе цели, Xray отдаёт приоритет `outboundTag` и игнорирует `balancerTag`;
- допускаются только стратегии `random`, `roundRobin`, `leastPing` и `leastLoad`; отсутствие стратегии трактуется как `random`;
- для `leastPing` и `leastLoad` должен быть указан ровно один корректный объект `observatory` или `burstObservatory`; частичный выбор отслеживаемых элементов допустим, для `burstObservatory` требуется объект `pingConfig`, а для `random` и `roundRobin` наблюдение необязательно;
- любое поле `fallbackTag` указывает на известное исходящее подключение.

Безвредные клиентские разделы на уровне агрегата, которые преобразователь не использует, допускаются только после успешной проверки структуры агрегата. Поддерживаемые отдельные профили строго проверяются на каждом используемом уровне.

Установлены следующие эксплуатационные ограничения: не более 4 активных запросов `/sub`, тайм-аут внешнего запроса 20 секунд, не более 3 HTTPS-перенаправлений, не более 5 МиБ в декодированном теле ответа и не более 100 000 сравнений тегов с префиксами агрегата в рамках всей подписки или одного запроса. Ограничение времени ответа в 30 секунд реализовано таймером цикла событий: оно прерывает асинхронную работу, но не может прервать синхронное преобразование JSON. Поэтому вычислительная сложность преобразования дополнительно ограничена размером входных данных в 5 МиБ и лимитом в 100 000 сравнений для всего запроса.

## Безопасность

- Compose публикует сервис только на `127.0.0.1`; не расширяйте адрес привязки, если доступ с других хостов не требуется.
- `.env` исключён из Git. Храните URL подписки в секрете и не вставляйте его в журналы, задачи, тестовые данные или файлы, добавляемые в репозиторий.
- Перенаправления остаются в пределах HTTPS и не могут содержать учётные данные или фрагменты.
- Входящие клиентские заголовки никогда не передаются внешнему источнику. Приложение самостоятельно добавляет только настроенный User-Agent, заголовок принятия JSON и запрос на кодирование identity.
- Ошибки и журналы не содержат URL внешнего источника, тело ответа, значения заголовков, адреса перенаправлений или вложенные причины ошибок.
- Рабочий контейнер выполняется с UID/GID `1000:1000`, корневой файловой системой только для чтения, небольшой временной файловой системой и запретом повышения привилегий.

## Разработка и тестирование

Поддерживаемая локальная среда выполнения — Node.js `24.20.0`. В соответствии с рабочим процессом репозитория устанавливайте зависимости и запускайте проверки в одноразовой копии проекта; не создавайте зависимости или результаты сборки в общем рабочем дереве.

```sh
npm ci
npm run typecheck
npm run lint
npm test
```

Параметр `PORT` задаёт порт прослушивания при непосредственном запуске Node.js, по умолчанию равен `17890` и принимает точное десятичное значение от `0` до `65535`. Значение `PORT=0` запрашивает временный порт и предназначено для тестов. Compose фиксирует порт контейнера на `17890`; пользователям Compose следует настраивать только `HOST_PORT`.

В тестах используются только синтетические адреса, учётные данные, сертификаты и данные. Проверка совместимости с настоящим источником запускается только явно: команда `npm run test:live` загружает `SUBSCRIPTION_URL` и необязательный `HAPP_USER_AGENT` из `.env`. Если при обычном запуске `npm test` URL отсутствует в окружении, такой тест пропускается. Тест не сохраняет и не выводит тело ответа, адреса, хеши или количество узлов:

```sh
npm run test:live
```

Проверить сформированный YAML с помощью Mihomo `v1.19.30`, версия которого зафиксирована контрольной суммой, можно командой:

```sh
npm run test:mihomo
```

Синтетическая проверка охватывает VLESS Reality, TCP TLS и WS TLS с отпечатком `360`, а также Hysteria 2. Проверить подписку поставщика без сохранения или вывода её содержимого можно командой:

```sh
npm run test:mihomo:live
```
